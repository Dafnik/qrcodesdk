QRCodeSDK, [qrcode](https://github.com/soldair/node-qrcode),
[qrcode-generator](https://github.com/kazuhikoarase/qrcode-generator), and

## Trade-offs

### Choose QRCodeSDK when

- You want one typed API for payloads, matrix options, and styling across SVG, Canvas, browser
  images, Node.js buffers, the terminal, and React, Vue, Svelte, or Angular components.
- Your code runs in several runtimes. Core has no Node.js or DOM dependency. Each runtime adds only
  the package it needs.
- You need shaped modules, finder and alignment styles, or center images with the same geometry in
  every graphical output.

### Consider another library when

- You need an API that has been stable for years. Every QRCodeSDK package is still `0.x`, so any
  release can break. See the [version policy](/project/release-policy/).
- You need Kanji mode, structured append, Micro QR, or GS1 data. QRCodeSDK does not implement them.
  See [Unsupported QR features](/reference/builder/#unsupported-qr-features).
- You need gradients or SVG post-processing callbacks. qr-code-styling supports both. QRCodeSDK
  colors each part with one solid color.
- You want a single dependency-free script. qrcode-generator ships every output in one package.
  QRCodeSDK splits outputs across Core, browser, Node.js, and framework packages.

### Costs of the QRCodeSDK approach

- Browser, Node.js, and framework output need more than one package. Keep their versions aligned.
- Renderers are synchronous. Load or decode center images before rendering.
- Generated bytes and markup can change between releases. Pin exact versions when you keep fixtures.

To choose a QRCodeSDK package, continue with [Choose your setup](/getting-started/choose-your-setup/).
