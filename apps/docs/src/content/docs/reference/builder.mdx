`qrcode()` creates an immutable builder from `@qrcodesdk/core`. Each options method returns a
new builder; the original builder remains unchanged. For how modes, versions, error correction, and
masks shape the symbol, see [How QR codes work](/learn/how-qr-codes-work/).

## Payload

The builder accepts a `string` or a non-negative safe integer. Use a string for values with leading
zeroes or values outside JavaScript's safe-integer range. At runtime, the builder rejects invalid
numbers but converts values of other types to text with `String()`. Check payloads from untyped
sources, as
[Payload types are not validated at runtime](/reference/errors/#payload-types-are-not-validated-at-runtime)
describes.

```ts
import {QRCodeBuilder, qrcode} from '@qrcodesdk/core';

qrcode('https://qrcodesdk.dev');
qrcode(1234567890);
qrcode().payload('payload supplied later');
QRCodeBuilder.create('https://qrcodesdk.dev', {errorCorrectionLevel: 'H'});
```

`QRCodeBuilder.create(payload, options?)` creates the same builder as `qrcode(payload)` and applies
matrix options in one call. `QRCodeBuilder.create()` without arguments matches `qrcode()`.

Typed [payload helpers](/reference/payloads/) serialize email, phone, SMS, geographic, and Wi-Fi
values into a payload string before you pass it to the builder.

QRCodeSDK generates QR Code Model 2 symbols. It supports numeric, alphanumeric, and UTF-8 octet payloads,
with optional automatic mixed-mode segmentation.

### Unsupported QR features

QRCodeSDK targets common application payloads in a single symbol. It does not support:

- Kanji mode. Japanese text is encoded as UTF-8 octets instead;
- structured append, which splits one payload across several symbols;
- Micro QR symbols;
- GS1 data;
- raw binary segments. Octet segments always contain the UTF-8 bytes of a string.

Use a library that implements these features when your scanner or industry standard requires them.

## Encoding modes

| Mode              | Accepted payload              | Use it for                                              |
| ----------------- | ----------------------------- | ------------------------------------------------------- |
| `numeric`         | Digits only                   | Numeric identifiers and digit-only payloads             |
| `alphanumeric`    | QR alphanumeric character set | Uppercase text such as `HELLO WORLD`                    |
| `octet`           | UTF-8 bytes                   | URLs, JSON, emoji, lowercase, and general text          |
| `auto` or omitted | Any supported payload         | Single-mode detection; optional mixed-mode optimization |

Without a segmenter, `auto` selects numeric for digits, alphanumeric for the QR alphanumeric
character set, and octet for other text. It encodes the complete payload as one segment. A concrete mode forces the entire payload into that mode.

### Optional mixed-mode optimization

Import `automaticSegmenter` to find the shortest-bit combination of numeric, alphanumeric, and
octet segments. The default generation path does not import the optimizer, so applications that
omit it avoid its bundle size and processing cost.

```ts
import {qrcode} from '@qrcodesdk/core';
import {automaticSegmenter} from '@qrcodesdk/core/segmenter';

const payload = 'ABCD12345678901234567890abcd';
qrcode(payload).mode('auto').matrix(); // Single segment, version 3.
qrcode(payload).mode('auto').segmenter(automaticSegmenter).matrix(); // Mixed segments, version 2.
qrcode(payload).options({segmenter: automaticSegmenter}).matrix(); // Auto is the default.
```

Explicit `numeric`, `alphanumeric`, and `octet` modes bypass the supplied segmenter. Use
`.mode('auto')` or `.mode()` to return to auto selection. Use `.segmenter()` or
`.options({segmenter: undefined})` to clear the segmenter.

Single-mode detection can produce a larger symbol than mixed-mode optimization, and a payload that
fits an optimized symbol can exceed the same pinned version without optimization.

Framework components accept the same callback through `options.matrix.segmenter`. The React, Vue,
Svelte, and Angular packages re-export `automaticSegmenter`, so applications import it from the
framework package.

A custom `QRCodeSegmenter` receives the original payload and `{version, eci}`. Return a non-empty
array of `QRCodeSegment` values with concrete modes and unencoded string payloads. Their text must
concatenate to the original payload.

Segments must not be empty, unless a single segment encodes an empty payload. A segment boundary
must not split a surrogate pair. Core validates each segment, UTF-8 encodes octet segments, and
packs numeric and alphanumeric segments in their respective QR modes.

With automatic version selection, the callback runs once per searched character-count group,
starting at versions 1, 10, and 27. With a pinned version, it runs once for that version. The
callback should be deterministic.

## Matrix options

`QRCodeMatrixOptions` contains only options that affect the encoded matrix:

| Option                 | Type                                               | Default   | Constraint                                     |
| ---------------------- | -------------------------------------------------- | --------- | ---------------------------------------------- |
| `mode`                 | `'auto' \| 'numeric' \| 'alphanumeric' \| 'octet'` | `'auto'`  | Forced mode must accept the entire payload     |
| `segmenter`            | `QRCodeSegmenter`                                  | omitted   | Used only in auto mode                         |
| `eci`                  | `boolean`                                          | `false`   | Only affects symbols containing octet segments |
| `errorCorrectionLevel` | `'L' \| 'M' \| 'Q' \| 'H'`                         | `'M'`     | Higher redundancy reduces payload capacity     |
| `version`              | integer `1`–`40`                                   | automatic | Pinned version must fit the encoded payload    |
| `mask`                 | integer `0`–`7`                                    | automatic | Pinned mask replaces penalty-based selection   |

TypeScript enforces these types and ranges. The builder does not check them again at runtime, so
values from JavaScript or untyped configuration can produce a matrix that scanners cannot read. See
[Matrix options are not validated at runtime](/reference/errors/#matrix-options-are-not-validated-at-runtime).

Set options individually or together:

```ts
import {qrcode} from '@qrcodesdk/core';

const builder = qrcode('Grüße ✅').mode('octet').eci(true).errorCorrection('H').version(4).mask(2);

const equivalent = qrcode('Grüße ✅').options({
  mode: 'octet',
  eci: true,
  errorCorrectionLevel: 'H',
  version: 4,
  mask: 2,
});
```

### ECI and UTF-8

Octet payload bytes are always UTF-8. Enabling `eci` emits ECI assignment 26 once, immediately before
the first octet segment, so scanners receive an explicit UTF-8 declaration. It adds 12 bits. With
`eci: false`, scanners may rely on heuristics for non-ASCII text.

No ECI header is emitted when a symbol contains no octet segment, so numeric- and
alphanumeric-only symbols are identical with either setting.

### Error correction

The levels `L`, `M`, `Q`, and `H` add increasing amounts of redundant data. The default is `M`.
Higher levels can tolerate more damaged or obscured modules, but reduce capacity and may select a
larger version. Use `H` with a center image, as [Add a center image](/guides/center-images/)
explains. [How QR codes work](/learn/how-qr-codes-work/#error-correction) lists how much each level
can restore.

### Version and mask

:::tip[Prefer automatic selection]
Most applications should leave both values automatic. Automatic selection returns the same result
for the same payload and options within one QRCodeSDK release. Pin `version` when the symbol must
have fixed dimensions, and pin `mask` when a compatibility target or an external fixture requires
a specific mask pattern.

Pinned options fix those encoding choices only and do not freeze the implementation. Matrix
modules, SVG markup, and raster bytes may still change between releases, as the
[release policy](/project/release-policy/#generated-artifacts) describes. When exact artifacts
matter, pin exact package versions and keep your own fixtures.
:::

When a pinned version cannot contain the payload, generation throws a `QRCodeError` with code
`PAYLOAD_TOO_LARGE` and `details.version`. See the [errors reference](/reference/errors/#payload_too_large).
Removing the override helps only if a larger version can fit the payload. If automatic selection also
fails, shorten or change the payload.

## Builder methods

| Method                     | Returns                   | Effect                                                         |
| -------------------------- | ------------------------- | -------------------------------------------------------------- |
| `.payload(value)`          | a builder with a payload  | Sets or replaces the payload                                   |
| `.options(options?)`       | a configured builder      | Merges all supplied matrix options                             |
| `.mode(mode?)`             | a configured builder      | Forces or clears the encoding mode                             |
| `.segmenter(segmenter?)`   | a configured builder      | Sets or clears optional mixed-mode segmentation                |
| `.eci(enabled?)`           | a configured builder      | Enables or clears the UTF-8 ECI declaration                    |
| `.errorCorrection(level?)` | a configured builder      | Sets or clears the error correction level                      |
| `.version(version?)`       | a configured builder      | Pins or clears the version                                     |
| `.mask(mask?)`             | a configured builder      | Pins or clears the mask                                        |
| `.matrix()`                | `QRCodeMatrix`            | Generates the matrix; TypeScript requires a payload            |
| `.renderer(renderer)`      | a builder with a renderer | Stores a renderer for a later call                             |
| `.render(renderer?)`       | renderer output           | Generates the matrix and invokes a supplied or stored renderer |

| Static method                             | Returns   | Effect                                               |
| ----------------------------------------- | --------- | ---------------------------------------------------- |
| `QRCodeBuilder.create()`                  | a builder | Creates a builder without a payload, like `qrcode()` |
| `QRCodeBuilder.create(payload, options?)` | a builder | Creates a builder with a payload and matrix options  |

In TypeScript, the builder's types prevent `.matrix()` or `.render()` before a payload is set, and
prevent `.render()` without either a stored or directly supplied renderer. The payload check exists
only in the types. Called from JavaScript, `.matrix()` on a builder without a payload does not throw
and encodes the text `undefined`. See
[Payload types are not validated at runtime](/reference/errors/#payload-types-are-not-validated-at-runtime).

Use `QRCodeBuilder` without type arguments to annotate a payload-configured builder in application
helpers. Its default type accepts builders with or without a stored renderer, so TypeScript allows
`.render()` without arguments through it. If no renderer was stored, that call throws
`RENDERER_MISSING` at runtime. Supply a renderer when calling `.render()` through the general type:

```ts
import {QRCodeBuilder, QRCodeSVGRenderer, qrcode} from '@qrcodesdk/core';

function toSVG(builder: QRCodeBuilder): string {
  return builder.render(QRCodeSVGRenderer());
}

toSVG(qrcode('https://qrcodesdk.dev'));
```

TypeScript checks matrix option names, types, and supported literal values. Payload format and
capacity are checked when the matrix is first requested; `qrcode()` and the option methods never
throw. See [Errors](/reference/errors/#factory-failures-and-render-failures).

## Matrix output and renderers

`.matrix()` returns a read-only `QRCodeMatrix` with flat, row-major module data. `size` is the
number of modules per side. `modules` is a frozen array with `1` for dark and `0` for light modules,
and `roles` is a frozen array with the role of every module, such as data, finder, or timing. The
module at column `x` and row `y` is at index `y * size + x` in both arrays. See
[Module roles](/reference/custom-renderers/#module-roles) for every role.

```ts
import {type QRCodeMatrix, qrcode} from '@qrcodesdk/core';

const matrix: QRCodeMatrix = qrcode('custom output').matrix();
const isDark = (x: number, y: number) => matrix.modules[y * matrix.size + x] === 1;
```

A `QRCodeRenderer<TOutput>` receives that matrix and returns `TOutput`:

```ts
import {type QRCodeRenderer, qrcode} from '@qrcodesdk/core';

const jsonRenderer: QRCodeRenderer<string> = ({size, modules}) =>
  JSON.stringify({size, modules: Array.from(modules)});

const direct = qrcode('renderer output').render(jsonRenderer);
const stored = qrcode('renderer output').renderer(jsonRenderer).render();
```

Built-in renderers use the same function signature. Custom renderers define their output geometry,
styling, validation, and return type. See [Custom renderers](/reference/custom-renderers/).
